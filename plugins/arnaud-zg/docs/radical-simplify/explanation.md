Explanation**

Why the skill works the way it does. To get something done, see the [How-to guides](how-to.md).

## The cheapest step is the one that no longer exists

Speeding up a step still leaves it to build, test, explain and maintain. Removing it costs nothing
afterwards. So the method asks whether something should exist before it asks how to make it better,
and every later step works only on what survived.

## Automating first locks the mess in

Automation is the most expensive step to undo: it turns today's process into code. Automate a step
that should have been removed and the waste becomes permanent and invisible. That is why automation
comes last, after the process has been questioned, cut, simplified, redesigned and sped up.

## Simple is designed around intent

Most complexity mirrors how an organisation is built, one screen per team, one approval per
department. The Simplify and Reimagine steps redraw the flow around what the user is trying to do,
which is why the skill favours defaults, context and one primary action over options.

## Why a fixed output

A model asked to "simplify" tends to polish what is there. A section per step makes each one
visible, so you can see what was questioned and removed, not only the final design. The closing
count is read from the original and the proposal, never estimated, so the claimed gain can be
checked.

## Why it proposes and does not edit

A redesign is a decision for a person. The skill writes it; changing the code is a separate request
once you agree.
